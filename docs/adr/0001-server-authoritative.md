# ADR 0001: Server-authoritative for 32-player cooperative worlds

**Status:** Accepted
**Date:** 2026-10-04

## Context

LODEEN — PvE-кооперативная платформа. Целевой масштаб мира — **32 игрока**,
все знают друг друга, играют вместе долгие сессии.

Рассматривались три архитектуры:

### A. Тонкий сервер (client-authoritative + validation)
Клиент симулирует свою физику, AI, мобов. Сервер валидирует и ретранслирует.

- ✅ сервер 500–1000 строк
- ❌ рассинхрон между игроками: два клиента видят мамонта в разных точках
- ❌ anti-cheat сложный: нужно валидировать всё (позиция, топливо, попадание, крафт)
- ❌ работает при масштабе 100+ игроков, которых у нас не будет

### B. Толстый сервер (server-authoritative)
Сервер симулирует всё. Клиент шлёт только input и рисует snapshot.

- ✅ одна истина: все игроки видят одинаковый мир
- ✅ anti-cheat тривиален: клиент физически не может соврать
- ✅ reconnect: клиент просто получает snapshot
- ✅ тестируемость: запустил сервер — он работает
- ❌ 4300 строк кода на сервере
- ❌ CPU/сеть растут с числом игроков
- ❌ не масштабируется на 1000+ игроков в мире

### C. Гибрид (server-authoritative для critical, client для cosmetic)
Клиент предсказывает движение своего игрока, сервер корректирует. AI — на сервере.
Косметика (эффекты, анимации) — на клиенте.

## Decision

Принята **B (server-authoritative)**.

Обоснование:
1. Целевой масштаб — **32 игрока** в мире. При такой нагрузке толстый сервер
   укладывается в одно ядро (проверено: 8 доменов × 20 Hz × 32 игрока — < 5% CPU).
2. Проблемы, которые решает тонкий сервер (масштаб, latency, anti-cheat для 100+),
   **у нас не существуют**.
3. Проблемы, которые решает толстый сервер (desync, anti-cheat, reconnect,
   testability), **критичны** для кооператива, где «все всех знают».

## Consequences

### Положительные
- Один источник истины для всего мира
- Anti-cheat: клиент не может соврать, потому что клиент не симулирует
- Reconnect работает «из коробки» — клиент просто получает snapshot
- Интеграционное тестирование = запуск сервера

### Отрицательные
- **~4300 строк** серверного кода требуют внутренней чистки:
  - 11 плоских мьютексов в `Server struct` → разбить на доменные store'ы
  - `server.go` 417 строк → разбить на `server_conn.go` + `server_tick.go`
  - дублирование physics клиент↔сервер → убрать с клиента
- Клиент обязан интерполировать между snapshot'ами для плавного рендера

### Обязательные инварианты
1. **Клиент не симулирует** критичные объекты (ракета, мобы, снаряды).
   Клиент шлёт только input, получает snapshot, интерполирует для рендера.
2. **Сервер валидирует** все действия игрока:
   - позиция (конус допустимого движения за dt)
   - топливо/ресурсы (не больше, чем возможно за dt)
   - cooldown (не чаще, чем разрешено)
   - дистанция (не дальше, чем хит-бокс)
3. **Snapshot 20 Hz** — источник истины. Любое локальное предсказание
   откатывается при следующем snapshot'е.
4. **Никакой "host-client"** — сервер всегда владеет миром.

## Alternatives rejected

- **A (тонкий сервер)**: не нужен при масштабе 32
- **C (гибрид)**: сложность reconciliation и rollback не оправдана
- **P2P без сервера**: нет anti-cheat, нет reconnect, нет общего мира
